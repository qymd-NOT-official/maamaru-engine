# 远征续派前补花

在「功能 → 玩法设置 → 远征」勾选「远征续派前补花」并保存。
常用安排、一键日课的远征安排，以及自动排班派遣共用此开关，默认关闭。
「今天的时间表」的远征配置独立保存「出发前补花」和伤势停止条件，
不读取玩法设置的开关；新班和旧班缺少此字段时默认不补花。
勾选后到点收菜、套用预设、补花，
核对恢复原队伍后才派出。补花耗时会顺延实际出发和归来时间；
尚未确认出发期间不会标为远征中，补花失败则本班停止，不反复重试。
伤势停止条件读取「刷花」配置；仍走共用安全出阵链，重伤不能出阵。

收取归来奖励并套用所选预设后，直接进入编队读取客户端 `/party/list`。
已在编队且已有本次所需响应时原地读取；保存使用 `/party/set_preset` 响应，
恢复使用游戏自动返回的 `/party/list`，不再为核对往返本丸。
选入第一圈的疲劳沿用该振客户端数据，打完再进入编队读取更新后的疲劳。
只在该队里挑上锁、等级大于1、疲劳不超过49的刀，按疲劳从低到高处理。
选人使用客户端唯一编号，沿用刀种、形态筛选及等级、乱舞、生存、侦察的可用证据；
同名无法区分时跳过，选择后编号回读失败则停止。
每振单人打1-1到疲劳100，自动阵型，兜底鱼鳞阵，每振最多40圈。

清队前使用游戏「记录部队一」保存原队伍（与已有自动整备使用同一记录，
会更新记录一），核对成员次序、刀装种类、马、御守及宝物字段。
游戏记录无法完整表达装备时，在清队前停止；不猜测装备恢复行为。
补花期间关闭出阵链的自动保存，避免把原记录覆盖成单人队。
结束后使用记录恢复，并用新的客户端响应核对原队员次序和装备；
刀装核对种类而非可损耗的个体编号。失败不续派。

用户数据目录 `state/expedition_sakura_pending.json` 在清队前保存恢复凭据。
停止、进程中断或取消留下未完成凭据时，普通刷花、保存记录及其他玩法出阵会被拦下。
下次远征管理先核对记录一仍是原队，再恢复；若记录已被手动覆盖则停止提示。
完成后保留 `restored` 凭据，不删除来源。恢复发生在预设换队之前。

验证包括：精确成员和素材刀排除、伤势设置传递、原记录保护、装备缺字段不清队、
失败出阵恢复但不续派、取消后的恢复凭据、错记录和错队员拒绝续派、
旧排班配置默认关闭，以及任务自己的补花不受排班接管旗标打断。
页面在隔离面板检查保存及窄屏；未自动运行真实远征补花整轮。
