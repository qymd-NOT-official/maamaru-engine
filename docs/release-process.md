# 发布验证：按风险检查，不重复跑

## 本机验证

- 普通修复和小功能只跑与本次改动相关的测试，不为了发版再在本机重跑全套；全量回归由既有 CI 完成。
- 大范围重构、跨玩法共用流程调整、核心状态或执行链路改动，额外进行本机全量回归。
- 用户数据目录、数据结构、迁移、安装器和自动更新属于高风险范围，即使改动行数少，也必须完成相关完整测试与隔离升级或回滚验证。
- 界面改动仍检查构建、关键页面及窄屏布局；同一实现已验证通过，发版时不再重复走一遍。
- 仅调整版本号或发布说明、没有继续修改运行逻辑时，复用刚完成的本机验证，不再重新执行相同测试。

## 发布流水线

- 保留现有 CI 的全量测试、构建和资源检查，不为普通发版额外重跑已经通过的同一提交检查。
- 保留私人配置与用户数据排除、轻量更新失败恢复、安装启动及卸载检查；这些是发布安全门，不以减少耗时为由关闭。
- CI 已完成隔离安装与更新验证时，普通发布不再在本机重复打包或安装。
- 出现测试失败、资源缺失或安全检查失败时，先处理原因，不绕过门禁发布。

## 发布后核对

- 确认正式 Release 对应预期版本与提交，不是草稿或预发布，且 latest 指向新版本。
- 核对官方发布附件齐全、上传完成，大小及 SHA-256 校验信息可用。
- 默认不再为了重复核对而下载安装器。只有附件异常、校验信息缺失，或本次明确需要检查实际下载与安装行为时，才额外下载验证。
- 检查结果以流水线和官方发布记录为准；未完成安装或更新验证时，不宣称已经验证通过。
