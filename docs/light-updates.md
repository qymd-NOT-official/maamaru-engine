# 轻量更新与完整安装包

轻量更新从支持目录式发布包的版本开始提供。旧版单文件启动器需要先通过完整安装包升级一次；尚未发布的源码功能不代表旧版已具备轻量更新能力。

## 玩家会看到什么

启动器「检查更新」显示可用版本、更新方式与下载大小。运行环境一致且文件完整时优先下载轻量更新包；旧版、运行环境变化或运行文件损坏时使用完整安装包。文件来自まあ丸官方 GitHub 正式 Release，并按文件名、大小与 SHA-256 校验。

下载完成后仍需玩家确认。任务正在执行时不能开始更新。轻量更新在独立目录中准备新版、逐文件校验并进行启动检查，通过后切换程序目录，再检查一次；失败时保留或恢复旧程序。完整安装包继续使用安装向导与原有回退流程。轻量下载失败时可以选择改下完整安装包。

轻量更新应用失败后，恢复启动的启动器会在本次运行中优先选择完整安装包。更新助手也会检查旧版面板或任务进程是否已经退出，仍在运行时暂不替换。

配置、日志、账本、小记等继续保存在既有用户数据目录。轻量更新不转换用户数据结构；结构变化需要另做兼容设计与迁移演练。

## 发布包

- 完整安装器和免安装 ZIP 都携带启动器、`_internal/` 运行文件、`manifest.json` 与 `update-manifest.json`。免安装 ZIP 必须完整解压，不能只拷贝启动器 EXE。
- `maamaru-update-v版本-运行环境指纹.zip` 只携带程序 EXE、界面、项目资源、配置模板和更新清单。Python、原生依赖及 OCR 模型等未变化的运行文件复用当前安装。
- 运行环境指纹包含运行文件路径、大小与 SHA-256。运行依赖或模型改变后指纹变化，客户端选择完整安装器。
- 安装包和更新包从干净发布工作区生成，不携带本机配置、截图、日志或用户数据。

## 校验与恢复

更新清单限定为版本 1、用户数据结构版本 1，记录目标版本、运行环境指纹与全部受管理文件。拒绝重复路径、路径逃逸、Windows 特殊路径、未知文件、用户数据以及文件大小或哈希不符。候选目录只放目标版本受管理的文件和卸载器文件；旧版多余文件保留在旧程序副本，不混入新版。

切换使用程序所在磁盘上的目录重命名，旧目录先留在旁边。成功后再向用户更新目录复制回退备份；跨盘复制失败时旁边的旧目录仍在。暂存、新版失败目录和旧目录暂不自动清理，以便排查与恢复。

启动检查在临时用户数据目录中导入启动器、面板和任务入口，检查面板资源，不连接游戏或执行任务。它用于发现程序缺失或无法加载，不能替代所有玩法的实机验收。

## 验证

`tests/test_light_update.py` 覆盖成功更新、切换后失败回退、损坏文件、路径校验、环境不匹配、完整安装回退选择及下载校验。`scripts/smoke_test_light_update.py` 对实际打包的程序做隔离启动、更新、损坏新版拒绝与用户数据保留验证。发布流水线在上传 Release 前执行轻量更新演练与安装、启动、卸载演练。
