# 选人页实例识别校准（2026-10-04）

从 `MAAAdapter.screenshot(force=True)` 的 MuMu 显存通道取得1280×720 BGR帧。
现场证据只放用户数据目录 `debug/selection-*.png`，不提交截图或客户端日志。

用既有名字行位置 `y` 定位数值，而非六行固定坐标：

- 乱舞等级：`(470,y-48)-(591,y-27)`，要求完整「乱舞 N级」。
- 属性栏生存：`(599,y-21)-(648,y+13)`。
- 属性栏侦察：`(876,y-21)-(925,y+13)`。
- 数字逐格OCR，只接受唯一的1至3位整数；上下裁切行保留缺证据。

正式共用选刀执行器对 `youzu:<serial>` 目标启用这些字段，复用原有刀种、
初/极筛选和完整名单扫描。仅取最近五分钟成功的 `/party/list` 目标数值；
旧档案不冒充即时状态。装备会影响显示值：刀装/马/宝物加成尚无完整映射，
带装备时不使用基础侦察；带宝物时也不使用基础生存。仍使用等级和乱舞，
不能唯一匹配就拒绝决定。禁止靠猜装备加成放行。

选入后必须读取本次决定之后的成功部队响应，核对请求的队号、槽号、实例编号。
没有新响应或编号不同返回未确认，不能继续装备和出发；队伍可能已变化。

同源帧通过正式 `_read_list_page` 复测：毛利藤四郎在滚动前后均读出
等级1、乱舞9、生存36、侦察49；三个1级狮子王中，乱舞2的唯一，
另外两个乱舞1、生存45、侦察25仍为歧义。匹配不会点第一条。
本次未实机点击决定；实际编号核对和失败中止通过模拟完整换人流程验证。

# 2026-10-04 找到即选入

唯一编号目标使用近期客户端完整刀账先核对同名同形态的可见数值是否唯一。
筛选后从当前页向下寻找，当前页找到就直接选入，不全表扫到底、不反滑核验、
不再拉回目标页；单页没有滚动条且找不到时直接停止。编号选入回读仍保留。
可见数值相同的同名副本直接跳过，扫描到底也不能补出身份信息。
